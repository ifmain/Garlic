# Поэтапное обновление Garlic

Начальная конфигурация входов и прямых выходов допускает GEX1, GEX2, GEX3 и GEX4. Старый клиент получает прежний список версий. Клиент gex4-r1 запрашивает GEX4 только при наличии признака `gex4-tlv` в аутентифицированном ответе сервера и проверяет подтверждение при открытии каждого WebSocket. Со старым сервером, объявляющим GEX1, он использует GEX1. Между входом и выходом сохраняется Relay v2.

В окружении службы `GARLIC_EXCHANGE_VERSIONS=1,2,3` отключает GEX4. Значение `1,2,3,4` включает его. Один и тот же список управляет объявлением возможностей и приёмом подключений. Изменения вступают в силу после перезапуска службы. Перезапуск прерывает активные потоки данного процесса. При переключении узлов по очереди сохраняйте работоспособный вход для остальных клиентов.

Сохраняйте прежние публичные адреса, сертификаты, настройки инфраструктурных ключей и пути файлов аккаунтов, очереди, сети, удостоверений и аренд. Перед заменой сохраните согласованную копию этих файлов и старые исполняемые файлы. При откате сначала верните старую программу с актуальными данными. Восстановление устаревшего снимка поверх новых записей приведёт к потере изменений.

В журнале новой службы строка `exchange_open` содержит согласованный номер протокола и, если клиент их прислал, платформу и обозначение выпуска. Событие относится к одному открытому WebSocket. У одного пользователя может быть несколько каналов. Точную версию старого приложения нельзя вывести из одного номера протокола.

Версия 0.3.0 обслуживается своими программами. Сохраните её прежние службы, состояние, домены и ключи на время миграции. Переключатель GEX действует только на семейство Exchange. [Размещение 0.3.0](legacy-v030.md)
Для привязки будущих подключений к UUID учётной записи задайте GARLIC_LOG_CLIENT_ACCOUNT=1. Платформу и выпуск сообщает приложение. Значение unknown сохраняет неопределённость для старых клиентов.

Пример Caddyfile.coexist.example предназначен для общего публичного адреса. Маршруты HTTP/2 /v1/tunnel и /v1/dns ведут в прокси 0.3.0. На пересекающихся путях запросы с прежним X-Garlic-Key попадают в службу 0.3.0, а запросы с Authorization поступают в современный координатор. Если ранняя установка обслуживала задачи без ключа, сохраните её отдельный адрес и прежние ограничения доступа. Выходы, доступные клиентам напрямую, также требуют проверки конфигурации. Пример проверялся с Caddy 2.10.2.
