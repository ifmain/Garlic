# Garlic 0.3.0 рядом с Garlic 0.9

[Архив 0.3.0](../../Garlic-v0.3.0-Linux-x86_64.tar.gz) содержит статические Linux x86-64 сборки `garlic-dns`, `garlic-infinite-storage`, `garlic-proxy` и `garlic-internal-network`. Исходники взяты из [сохранённого тега](../../../recovery/github-v0.3.0/Cargo.toml).

Для действующих клиентов 0.3.0 сохраните настроенные у них адреса и маршрутизируйте их к соответствующим службам из старого комплекта. Разворачивайте службы с отдельными параметрами, портами, файлами состояния и ключами. [Исходная схема HTTPS/HTTP2](../../../recovery/github-v0.3.0/docs/PROXY.md) · [Исходная схема очереди](../../../recovery/github-v0.3.0/docs/TASK_EXCHANGE.md)

| Старая операция | Служба 0.3.0 |
| --- | --- |
| `POST /v1/tunnel`, `POST /v1/dns` | `garlic-proxy server` за HTTPS-фронтендом с HTTP/2 и h2c до локального backend |
| `POST /execute` | `garlic-infinite-storage` |
| `POST /tasks`, `GET /tasks/{id}` | `garlic-dns`, команды выполняет `garlic-infinite-storage` |

Перед запуском проверьте содержимое командой `sha256sum -c SHA256SUMS` из распакованного каталога. Для прокси в комплекте сохранён исходный `configs/Caddyfile`. Для задач программы из исходной версии слушают loopback. При удалённом доступе нужен HTTPS-фронтенд, который сохраняет заголовок `X-Garlic-Key`. Для прокси настройте прежний `GARLIC_PROXY_KEY`, а между доверенными узлами используйте `GARLIC_EXIT_KEY`. Рабочие значения ключей задаются в окружении служб.

На стенде проверены прямые и отложенные задачи на бинарниках из архива. Отдельная проверка исходного HTTPS/HTTP2-клиента и входа передала двоичные блоки и DNS через подставной выход. Действующие домены и публичный выход 0.3.0 в этом прогоне не использовались. [Результаты](../../rust/tests/current-results/backward-compatibility.json)
