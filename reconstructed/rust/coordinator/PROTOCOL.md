# Сервер Garlic. Контракт модулей обмена, ABI 1

## Обнаружение и допуск

Клиент узнаёт возможности узла через аутентифицированный GET `/v1/auth/info`. Поле `exchange_version: 1` обозначает формат discovery. Массив `exchange_versions` перечисляет включённые GEX2 и GEX3 в порядке возрастания. Наличие `gex4-tlv` в `exchange_extensions` объявляет GEX4. Ответ на анонимный запрос содержит только базовые сведения. Для парка старых клиентов оставляйте GEX2 включённым: сохранённый Windows-клиент в локальной конфигурации выбрал GEX2 даже при предложенных 2 и 3.

Клиент открывает поток через POST `/v1/infinity/streams`, затем запрашивает WebSocket по `/v1/exchange/{uuid}` с заголовком `x-garlic-exchange-version`. Для 2, 3 или 4 сервер возвращает тот же заголовок с выбранным значением. Неизвестная или выключенная версия даёт HTTP 400. Пустой UUID отклоняется. Отсутствие заголовка интерпретируется как запрос версии 1, доступные модули начинаются с версии 2. Проверки пользователя, принадлежности потока и устройства выполняет ядро. Повторная проверка авторизации открытого канала выполняется каждые пять секунд.

## Передача данных

Целые числа в заголовках передаются старшим байтом вперёд. WebSocket передаёт двоичные сообщения. Ping/Pong и Close сохраняют обычную семантику WebSocket.

| Модуль | Сообщение WebSocket | Внутренний пакет |
| --- | --- | --- |
| GEX2 | Фрагмент с заголовком GEX2 | Базовый пакет с меткой GEX1 |
| GEX3 | Такой же фрагмент GEX2 | Пакет с меткой GEX3 и четырьмя байтами выборочного подтверждения после последней записи |
| GEX4 | Метка GEX4, длина области расширений u16, расширения, один пакет | Базовый пакет с меткой GEX1 |

**Пакет.** После четырёх байтов метки следуют номер последовательности u64, непрерывное подтверждение u64 и слово u32. Старший бит слова содержит флаг, остальные биты задают число записей (0–256). Непустому пакету требуется ненулевой номер. Каждая запись содержит ненулевой UUID потока (16 байтов), тип u8, длину u32 и данные. Типы 0–3 обозначают данные, запрос эха, ответ и закрытие. Максимальная длина данных записи равна 0x100028, максимальная длина пакета — 0x102028. Лишние байты отклоняются. Номер и подтверждения общие для каналов одной пары «пользователь, UUID обмена». Для GEX3 бит 0 выборочного подтверждения относится к следующему номеру после непрерывно подтверждённого.

**Фрагменты.** Заголовок содержит метку GEX2 и четыре u32: идентификатор сообщения, смещение, полную длину и длину полезной части. Предел сообщения сборщика — 0x102029 байтов, предел записи — 16000 вместе с заголовком. Первый фрагмент начинается с нулевого смещения. Последующие фрагменты продолжают то же сообщение без пропусков. Нулевой идентификатор с нулевой полной длиной обозначает заполнитель. Пакет передаётся обработчику только после сборки. Сборщик и счётчик исходящих сообщений принадлежат отдельному WebSocket.

**Расширения GEX4.** До 1024 байтов TLV. Каждый элемент содержит тип u8, длину u8 и значение указанной длины. Незнакомые типы 0–127 пропускаются. Типы 128–255 и неполные элементы отклоняются. Текущий отправитель записывает нулевую длину области расширений.

## Горячая замена

Встроенный набор инструкций находится в `src/exchanges/modules-v1.json`. Узел может читать внешний набор по пути `GARLIC_PROTOCOL_MODULES`. При старте сервер проверяет его до изменения состояния. Запись содержит номер версии, операцию сборки кадра и операцию декодирования тела. Для фрагментируемых версий параметр `record_size` задаёт исходящий размер записи от 1024 до 16000 байтов включительно. Входной предел остаётся равным 16000. Интерпретатор принимает комбинации из таблицы выше. Добавление совершенно нового примитива кодека требует новой сборки ядра.

Номера 2–4 закреплены за совместимыми сочетаниями. Диапазон 128–255 доступен для дополнительных модулей. Например, `{"version":128,"frame":"tlv","body":"selective-ack"}` помещает пакет GEX3 с выборочным подтверждением в TLV-кадр GEX4. Сервер публикует номера дополнительных модулей в отдельном массиве `exchange_module_versions` только при их наличии. Клиенту такого модуля нужно заранее знать его описание. Исходные метки внутри пакетов сохраняются. Сервер проверяет выбранную версию при каждом upgrade.

Публикуйте весь JSON атомарной заменой файла. Пример внешнего набора:

```json
{"abi":1,"modules":[
  {"version":2,"frame":"fragments","body":"base"},
  {"version":3,"frame":"fragments","body":"selective-ack","record_size":8192},
  {"version":4,"frame":"tlv","body":"base"}
]}
```

Наблюдатель проверяет файл раз в секунду. Предел — 16 КиБ. Неизвестное поле, повтор версии, ошибка чтения или несовместимая комбинация сохраняют последнюю принятую таблицу. Пустой список закрывает приём новых каналов всех трёх версий. Переменная `GARLIC_EXCHANGE_VERSIONS` задаёт верхнюю границу доступных версий. При upgrade ядро копирует выбранное описание в канал. Уже принятый канал использует его до закрытия. Повторное подключение после обрыва проходит допуск по текущей таблице. Откат выполняется публикацией предыдущего файла.

## Роли и пределы совместимости

`garlic-server --role entry` запускает вход. Аргумент `--grpc-route FILE` добавляет существующий входной шлюз. `--role intermediate` запускает координатор, `--role exit` — выход с локальным worker. Прежние имена `coordinator` и `gateway` поддерживаются. Ограниченный адаптер **Xray for Garlic** можно отдельно запустить как `--role xray-for-garlic --grpc-route FILE`. Он обслуживает существующие реализации локального VLESS и Trojan gRPC. Отдельный процесс можно остановить независимо от ядра. TLS и конфигурация внешнего подключения задаются инфраструктурой входа. Внутрисетевой транспорт в этой версии сохраняет Relay v2.

Выход учитывает занятые и ожидающие подтверждения потоки по UUID пользователя и логическому выходу. При ёмкости от двух потоков часть мест резервируется для других пользователей. По мере появления пользователей квота новых открытий делится между ними. Действующие соединения продолжают работу. Администратор получает тот же лимит потоков при сохранении привилегии на количество устройств. Ограничение относится к числу потоков. Оно не задаёт лимит байтов в секунду.
